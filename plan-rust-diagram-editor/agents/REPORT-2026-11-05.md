## 3. How the work was split

**Every file has exactly one owner.** Agent A owns the look: `shell.rs` (layout only), everything under `src/ui/` except `commands.rs`, fonts, the screen tests and the UI docs. Agent B owns behavior: `commands.rs`, `app_state.rs`, `dispatch.rs`, `presentation.rs`, `intent.rs`, `editor_state.rs`, `viewport.rs`, `drafts.rs`, the `diagram-core`, `diagram-canvas` and `diagram-storage` crates, `Cargo.toml`, and the logic tests.

**The agents meet at one seam.** B builds a read-only `Presentation` (what the screen shows) from the app state. A's views draw it and push `UiIntent`s (what the person did). B's `dispatch::apply` turns those intents into state changes. Views never change state themselves.

```text
[A] control drawn from Presentation  ->  [A] view pushes UiIntent  ->  [B] dispatch::apply
                                                                            |
[A] view draws the result  <-  [B] presentation::build  <-  [B] app / editor / model state
```

**The command catalog is the single source of truth.** A's tests read labels and availability from the catalog, and the routing tests loop over every command. A new command is therefore tested on both sides automatically.

## 8. Corrections made by the coordinator during the merge

1. **A broken Python test, caused by the coordinator's gate change.** In `bae503b`, R1-01 was made to depend only on R0-01, as the user decided. That broke `test_committed_ui_tasks_gate_the_right_milestones`, which still expected R1-01 to wait for UI-12.
2. **The gate change went too far.** After it, the native UI review (UI-12) and the foundation gate (R0-05) no longer blocked *anything*, including the release. The user approved *starting model work early*, not skipping those reviews.
3. **The fix:** UI-12 and R0-05 are now prerequisites of **R2-08**, the class vertical-slice walkthrough. So model work stays parallel, but the M2 milestone and the release still need the native UI review and the foundation decision. The Python test now checks both facts, and the roadmap files (`roadmap.json`, `ROADMAP.html`, `rust-backlog.csv`) were regenerated.
4. **Line endings only.** The roadmap generator rewrites `rust-backlog.csv` with different line endings each time it runs. When the content didn't change, the file was restored.

## 9. What is not done or not verified

Read this before saying anything works.

- **The real model is not connected to the editor yet.** The screen still edits the sample classes. Add class, Connect, members, Undo/Redo, Save and Export stay **disabled, each with its reason**. Nothing claims a save or an undo that didn't happen. The next tasks are UI-13 to UI-15.
- **Saving to a file:** R1-05 and R1-06 (the `.dgram` schema and transactional save) are not started.
- **No real-window check.** The container lacks `libxkbcommon-x11`, so the app panics at start under a virtual display. **No real-window screenshots were taken**, and none are claimed. All UI checks are headless (egui_kittest through the accessibility tree).
- **Windows, Arabic and assistive technology:** Windows, Arabic shaping and bidi, IME input, Narrator/NVDA and 150%/200% scaling were not tested. These remain R0-04 and UI-10.
- **Rename drafts are only partly connected.** The full Enter / Escape / Resolve-edit policy exists in B's code, but A's shell keeps `draft_events` off. One B journey test (`escape_after_typing_a_valid_name_should_keep_it`) still expects names to commit while typing (A's request 10). Until that is updated, valid names commit as you type, as before.
- **Not yet built in the screens:**
  - header: the save-state badge and the Undo/Redo action labels;
  - tabs: close buttons;
  - tool row: the relationship-kind chooser and the Arrange menu;
  - navigator: Diagrams/Model tabs and row actions;
  - board: edges and connection previews;
  - inspector: the relationship and multiple-selection layouts;
  - status bar: Grid, Snap and zoom as buttons;
  - dialogs: every dialog except Resolve edit;
  - the validation drawer.
  Most of these are waiting for presentation fields (A's requests 1–9).
- **Noto Sans as the main font** pushes the welcome screen 16 points beyond 800×500, so the fonts are fallbacks only for now.
- **Audit limit:** the audit can't see scroll areas, so the object search inside the 800×500 drawer is audited only at 1280×800 and 1440×900.
- **History budget:** history is limited to 500 transactions. The planned 64 MiB memory budget is not measured.
- **Grouped commits:** some commits contain several tasks (B-1 to B-3, B-4 to B-10, R1-01 to R1-04, A-1 to A-7 with A-10), not one task each as the briefs asked.

## 13. Merging into main

When the work was finished, `main` had moved on. PR #4 had merged eight commits in the meantime: UI-05 (navigator and tabs), UI-06 (typed intents), UI-08 (contextual inspector), UI-11 (notation contract), the status bar moved out of `shell.rs`, and a maintainability skill with a check script. That work was built on a separate design, and its tracker marks UI-05, UI-06, UI-08 and UI-11 as `done`, with real-window screenshots.

**A trial merge**, made in a scratch copy so no branch was changed, conflicted in 13 files: `shell.rs`, `ui/commands.rs`, `ui/inspector.rs`, `ui/mod.rs`, `ui/navigator.rs`, `ui/status.rs`, three test files, the UI progress page and the three roadmap files. Both sides had added their own `navigator.rs`, `inspector.rs` and `status.rs`. Resolving the conflicts would have meant choosing one of two competing UI designs, file by file.

**The user's decision: keep main's UI.** The pull request is built on the latest `main` and adds only the parts that don't overlap:

| Included | Why it is safe |
|---|---|
| `diagram-core`: typed IDs, model, validation, reversible commands, history (R1-01 to R1-04) | Main did not touch this crate. The only thing main's desktop uses from it is `ProjectName`, which is unchanged. |
| `diagram-canvas`: checked viewport transform and picking | Main did not touch this crate, and nothing in main's desktop uses it yet. |
| The agent briefs, the task and test plan, this report, B's evidence page | New files only. |
| `roadmap.json`: R1-01 to R1-04 `done`; R1-01 depends on R0-01; R2-08 also needs UI-12 and R0-05 | Only these five task lines change. Main's statuses for UI-05, UI-06, UI-08 and UI-11 are kept as they are. |
| `test_build_rust_roadmap.py` | Checks the two dependency facts above. |

| Not included (kept on `ccr-9e509aa7-1fyp6k`) | Why |
|---|---|
| All 53 desktop files: `presentation.rs`, `intent.rs`, `dispatch.rs`, `editor_state.rs`, views, extra commands, D1–D3, the tests of both agents | They compete with main's reviewed screens. Porting the useful behavior (Hand, zoom and Fit, selection, drafts, Escape layering, F6, the extra commands, D1–D3) onto main's design is the next job. |
| A's evidence page and A's fonts commit | These describe and support the desktop version that wasn't merged. The fonts can come with the port. |

**Known overlap to resolve during the port:** `diagram-core/src/notation.rs` (from B) and main's `ui/notation.rs` (UI-11) both describe the Class notation. The port should keep one source: the core one for model rules, and main's for what the screens show.

The PR branch is `ccr-9e509aa7-1fyp6k-model`. It starts at main's tip, so it merges into `main` without conflicts.
